# Data provenance model

Every source, import, asset attribute, observation, and derived result must be traceable. Missing data stays missing; estimates are never presented as measurements.

## Status vocabulary

`VERIFIED` — supported by an authoritative source or documented verification procedure. `SOURCE_REPORTED` — stated in a source but not independently checked. `DERIVED` — reproducibly calculated from documented inputs. `ESTIMATED` — produced by a documented method with uncertainty. `SIMULATED` — generated by a physical or mathematical simulation. `UNKNOWN` — no reliable value. `CONFLICTING` — credible sources disagree.

## Required source record

- Stable internal source ID and source organization
- Original URL, file, service, or document citation
- Acquisition/import timestamp; publication date if known
- Dataset/version identifier if known
- License and use restrictions, or explicitly UNKNOWN pending review
- CRS and datum; source coordinate precision/accuracy if known
- Geographic and temporal coverage
- Original identifiers retained without overwriting
- Validation state, checks performed, errors, and reviewer/evidence
- Source-quality and temporal-validity notes

## Attribute-level provenance

Every important attribute carries value, unit where applicable, status, source reference, source field/document, observation or effective date, method for DERIVED/ESTIMATED values, uncertainty where relevant, and validation evidence. Conflicting inputs remain represented as conflicts until adjudicated. Installation year and pipe geometry remain UNKNOWN when absent.

## Data domains

Keep separate namespaces and access policies for authoritative geographic/asset data, real telemetry, public research benchmarks, synthetic/simulated experiments, and model predictions/derived results. Benchmarks must never populate the Delhi operational map or its asset registry.

Staged review records carry an explicit `data_domain`: `OPERATIONAL_CANDIDATE`, `RESEARCH_BENCHMARK`, `SIMULATION`, `SENSOR_TELEMETRY`, or `MODEL_OUTPUT`. This classification does not itself grant promotion or establish source authority.

## Import rules in this milestone

Validation is non-persistent. An explicit staging action may save only the manifest, feature count, and canonical dataset hash with `PENDING_REVIEW` status; it never saves feature geometry or promotes records to the asset registry. The submitted manifest must identify source organization, original reference, acquisition date, license/restrictions, CRS, dataset/version, and quality/accuracy state (or explicitly state unknown). GeoJSON must be a FeatureCollection with structurally valid geometry; invalid or absent geometry is rejected. Authenticated review and promotion to an operational dataset are not implemented.
